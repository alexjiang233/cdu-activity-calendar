# 图形管理台：维护者补充说明

用户入口为根目录“打开活动管理.vbs”，图文指引为“先看这里.html”。只绑定127.0.0.1，默认8768端口，不对外开放。标准库实现，无常驻云端后台。

## 数据边界

- 正式值仍在campus.sqlite3；admin-state.json只保存候选、确认进度、字段归属与发布状态，不是第二套已收录事实库。
- 原件上传只进入data/inbox，既不自动提取，也不入库或上线。复制整理请求后由维护执行者实际处理。
- 已通过原有证据管线的增量先用prepare-review生成候选。待确认、跳过的候选不进入正式DB，因此不进入预览或网站。
- 用户确认后才事务入库，自动备份。修改范围仅名称、类型、补充说明和精选选择，不允许GUI改原文引句、来源或日期。
- 补充说明使用独立editorial_note，原文事实保留。旧数据同步会根据字段归属保留用户手动修改，不能覆盖成机器生成值。
- 撤销恢复上一份正式数据，保留修订历史；如涉及确认卡片，放回待确认。

维护执行者准备卡片：

```sh
python scripts/manage_content.py check
python scripts/manage_content.py prepare-review --batch-id 唯一批次 --reason "说明补齐内容" --expected-revision rev-当前版本
```

这是完整本地环境的旧证据适配入口，不绕过正文和附件校验，也不是任意JSON导入接口。旧sync-legacy仍供执行者直接接入已授权批次；用户选择人工确认后，优先prepare-review。

## 发布

管理台只尝试使用已有Git凭据，不触发登录，不保存或显示密码、令牌。没有可用授权时显示“交给Sol发布”，冻结HTML和请求到data/publish-outbox。浏览器中的GitHub登录不等于本地程序已有授权。

Sol接手发布时先读取request.json，核对当前revision、文件SHA、内容隐私、预览与原件；提交GitHub后验证Pages全文匹配，再更新admin-state.json里的last_published。不可把awaiting_publisher当作上线。

有本地授权时后台上传到固定仓库，只有线上全文与预览一致后显示成功；上传后暂未匹配显示未确认，不自动重复提交。上传期间阻止内容写入；预览过期或哈希变化拒绝发布。

## 安全与运行

写操作需要同源Origin和随机会话令牌；Host校验防止DNS重绑定；静态文件使用允许列表，不能浏览data或任意目录。上传限制50MB，仅本地存储，不解压或执行。渲染外部文本使用textContent，不拼接HTML。

默认不加入3298条队列；“拿10条试试”只将已收录活动送到本机确认列表。测试使用独立数据库和--no-publish，禁止在正式库制造演示修改。

后台由双击启动器启动。当前不提供安装包、系统开机自启或在线远程协作，避免增加用户操作与维护负担。

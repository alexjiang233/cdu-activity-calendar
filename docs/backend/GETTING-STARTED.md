# 前后端与内容工作台

## 现在怎么用

本机已安装好：双击项目根目录「打开活动管理.vbs」，或打开 <http://127.0.0.1:8790/manage/>。使用原维护者账号登录。

首页和活动／指南／校园查询列表均有「＋ 添加」。新增活动与指南先隐藏：写好标题，添加每届通知或指南步骤，再把公开状态改为公开并发布。校园查询同样先隐藏。

活动页的「通知版本」可以添加某年某份公告；通知页顶部入口可添加报名、材料、奖励等分条信息和学院／级别标签。同一活动沿用一条记录，不需要每年再创建活动。

指南页可以添加步骤、问答和资料来源；进入步骤可添加其中的具体条目。关联选择框支持输入关键词筛选选项。

「设置与维护」已接替旧后台：分类、学院、级别、来源、分组、指南子条目、全部草稿、导入记录、变更记录、站点设置、账号与权限组都在新版内。旧 `/admin/` 书签跳转新版，旧表单不能再写入。

活动／指南／查询用隐藏代替整条删除，保留历年资料。没有子记录的事实、步骤、条目、问答、来源和标签可以移除，在修改记录中恢复；有依赖的父记录禁止连带删除。

只有站点所有者可管理账号和权限组；无法停用自己。密码通过专门表单设置，不写入修改快照。权限组可设置各栏目查看、新增、修改、删除权限。

## GitHub 里的组成

- 根目录 `index.html`：现有 GitHub Pages 静态网站，保持可用。
- `frontend/src/`、`frontend/build.py`：使用后端接口的新前台及其构建入口。
- `backend/`：Django、只读公开 API、新版维护界面、迁移命令和测试。
- `deploy/`：生产部署配置示例。

上传代码不等于部署后端。GitHub Pages 不能运行 Python／数据库；后台仍在本机，公网后端需要另外部署到服务器。

运行数据库、维护者账号、会话、密钥、原始归档、隐藏内容与本地备份均不上传 GitHub。完整内容继续保存在本机库中。

## 新电脑安装（给技术协作者）

```powershell
python -m venv .venv-backend
.\.venv-backend\Scripts\python -m pip install -r backend/requirements.txt
.\.venv-backend\Scripts\python frontend/build.py
.\.venv-backend\Scripts\python backend/manage.py migrate
.\.venv-backend\Scripts\python backend/manage.py createsuperuser
.\.venv-backend\Scripts\python backend/manage.py runserver 127.0.0.1:8790
```

新安装默认是空库，可手动添加内容。搬迁完整资料时，另行安全复制现有 `backend/db.sqlite3`（停服务后复制，或用 SQLite 在线备份），不要将带账号与隐藏资料的运行库提交到公开仓库。旧归档迁移命令说明见 `manage.py help migrate_legacy`。

生产环境使用 PostgreSQL + gunicorn + Caddy。`DEBUG=0` 时必须提供随机密钥、域名、数据库配置；配置样例不代表已完成实机部署。前台与后台同源，`/manage/`、`/api/`、`/static/` 均需转发 Django。

## 功能对照

| 原后台 | 新版位置 |
| --- | --- |
| 新建、编辑活动／指南／校园服务 | 首页快捷添加、各内容列表 |
| 通知、事实、参与条件、日期 | 活动 → 通知版本；通知 → 分条信息 |
| 学院、级别与类别 | 设置与维护 → 分类与学院标签／通知标签 |
| 来源、学院拆分卡 | 设置与维护 → 公告来源／学院展示分组 |
| 指南步骤、条目、问答、资料出处 | 指南页上方的添加／管理入口 |
| 首页候选与精选批量设置 | 活动列表勾选后批量操作 |
| 草稿、发布、回退、历史导入 | 草稿列表、修改记录、导入记录 |
| 原始结构画像 | 设置与维护 → 原文结构档案（只读） |
| 站点信息与策略 | 设置与维护 → 站点设置 |
| 用户、密码、权限组 | 设置与维护 → 维护者账号／权限组 |

原始扩展字段、迁移布局与导入来源标识继续保留，不开放无约束编辑。批量导入仍用带校验和断点的既有命令，不增加一个可任意执行脚本的网页入口。
